API vs. webscraping por dashboard: o diagnóstico honesto da fragilidade técnica e a estratégia de resiliência do URBI.A.

O dado mais crítico do levantamento

83,2% dos 125 indicadores do Plano Diretor de Curitiba não possuem API oficial. Dependem de webscraping — extração automatizada de portais públicos que pode ser interrompida por mudanças nos sites de origem. O URBI.A. assume essa realidade com transparência e implementa três camadas de resiliência.

Estratégia de resiliência

Como o URBI.A. mitiga a dependência de webscraping

🔔

Camada 1 — Alertas automáticos

Cada pipeline de webscraping possui monitoramento ativo. Se o portal de origem alterar sua estrutura ou ficar offline, um alerta é disparado imediatamente para o Data Steward responsável. O usuário vê o dado com o carimbo "atualizado em [data]" — nunca dado incorreto.

🗄️

Camada 2 — Cache histórico protegido

O Data Warehouse mantém o último valor válido de cada indicador mesmo quando a fonte falha. Dashboards exibem o dado mais recente disponível com transparência sobre a data da última atualização bem-sucedida.

📢

Camada 3 — Advocacia por APIs oficiais

O IPPUC utilizará o URBI.A. como instrumento de diálogo junto a DATASUS, SESP, SANEPAR e URBS. A meta é elevar de 14,4% para 40% a proporção de indicadores via API até 2027.
